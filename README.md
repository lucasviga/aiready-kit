# claude-kit

My personal collection of **[Claude Code](https://claude.com/claude-code) skills and rules**, plus a terminal wizard that installs them.

```
┌  claude-kit   skills & rules for Claude Code
│
◆  What would you like to do?
│  ● Install skills / rules
│  ○ Show status
│  ○ Uninstall
│  ○ Create new skill / rule (scaffold inside this repo)
│  ○ Exit
└
```

## Quick start

You need **Node.js 18+**.

```bash
npx github:lucasviga/claude-kit
```

This opens the wizard. Pick what you want, choose **Global** (`~/.claude`, every project) or **This project** (`./.claude`, commit it with the repo), and you're done. Restart Claude Code or open a new session to load the changes.

### Command-line usage

```bash
npx github:lucasviga/claude-kit list                              # what's available and what's installed
npx github:lucasviga/claude-kit install skill conventional-commits
npx github:lucasviga/claude-kit install rule general-coding --project
npx github:lucasviga/claude-kit install all                       # everything
npx github:lucasviga/claude-kit uninstall skill conventional-commits
```

| Flag        | Effect                                                        |
|-------------|---------------------------------------------------------------|
| `--project` | Install into `./.claude` instead of `~/.claude`               |
| `--link`    | Symlink instead of copy (only when running from a git clone)  |
| `--force`   | Overwrite items that are already installed                    |

### Working from a clone (recommended for editing)

```bash
git clone git@github.com:lucasviga/claude-kit.git
cd claude-kit
npm install
npm start            # wizard; choose "Symlink" so edits apply instantly
npm link             # optional: makes `claude-kit` available everywhere
```

## Skills vs. rules

| | Skills | Rules |
|---|---|---|
| **What** | A folder with a `SKILL.md` (plus optional scripts and references) | A single Markdown file of instructions |
| **When it loads** | On demand, when Claude decides the task matches the `description` (or you call `/name`) | At the start of every session (or only for matching files when `paths:` is set) |
| **Installed to** | `~/.claude/skills/<name>/` or `./.claude/skills/<name>/` | `~/.claude/rules/<name>.md` or `./.claude/rules/<name>.md` |
| **Good for** | Workflows, procedures, tooling ("how to write a commit", "how to deploy") | Conventions and preferences ("always use pnpm", "TypeScript style") |

## Adding your own

```bash
npm start                       # → "Create new skill / rule"
# or
node bin/cli.js new skill my-skill
node bin/cli.js new rule my-rule
```

1. Edit the generated `skills/<name>/SKILL.md` or `rules/<name>.md`.
   - **Skills:** the `description` in the frontmatter decides when Claude uses it. Say *what* it does and *when* to use it.
   - **Rules:** add `paths:` in the frontmatter to load the rule only for matching files.
2. Run `npm run docs` to regenerate the catalog and install guides above.
3. Commit and push.

## Repository layout

```
bin/cli.js            CLI entry point (wizard + commands)
src/                  catalog loading, install logic, wizard UI
skills/<name>/        one folder per skill (SKILL.md + optional files)
rules/<name>.md       one file per rule
templates/            templates used by "Create new"
scripts/gen-readme.js regenerates the Catalog section of this README
```
