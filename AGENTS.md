# AGENTS.md

aiready-kit — a terminal wizard and CLI that detects the AI coding tools on your machine (Claude Code, Cursor, Codex, Copilot CLI, Gemini CLI) and installs rules and skills for them, globally or into a project.

## Project map

| Path | What it holds |
|------|---------------|
| `bin/cli.js` | CLI entry point (`aiready-kit` bin): wizard, list, install, uninstall, update, new, agents, detect |
| `src/` | `catalog.js` (loads rules/skills + frontmatter), `harness.js` (supported tools, detection, target folders), `install.js` (copy/symlink into each tool's folder; Cursor rules as `.mdc`), `agents.js` (AGENTS.md managed block, CLAUDE.md/GEMINI.md imports, `~/.codex/AGENTS.md`), `summary.js` (success message), `update.js` (fetch the latest kit and refresh installed items), `wizard.js` (interactive prompts) |
| `rules/` | Source rules (`*.md` with frontmatter) — the catalog |
| `skills/` | Source skills (`<name>/SKILL.md` + `references/` + `assets/`) — the catalog |
| `templates/` | Scaffolds used by `aiready-kit new` |
| `scripts/gen-docs.js` | Generates the README catalog table and `docs/catalog.md` |
| `docs/` | Nested docs linked from the README (`catalog.md` is generated) |
| `.github/workflows/check.yml` | CI: install, docs check, `list` smoke test |
| `.claude/`, `.agents/` | This repo's own installed copy of the kit (generated by `install all --project`) |

## Tech stack

- Node.js >= 18, ESM (`"type": "module"`), no build step
- @clack/prompts (wizard UI), picocolors (colors)

## Services and ports

None — this is a CLI; it does not open any port.

## Install

```bash
npm ci
```

## Run

```bash
npm start                 # wizard (needs a TTY)
node bin/cli.js list      # list rules and skills
node bin/cli.js detect    # AI coding tools found on this machine
node bin/cli.js -h        # help
```

## Test

```bash
npm run check             # fails if README/docs are out of date with rules/ and skills/
node bin/cli.js list      # smoke test
```

TODO: no unit test suite yet.

## Build

None. After changing `rules/` or `skills/`, run `npm run docs` and then `node bin/cli.js install all --project --force` to refresh `.claude/`, `.agents/` and AGENTS.md.

## AI coding rules

Read and follow every rule below before changing code in this repository.
Skills hold detailed guidance, examples and templates: open a skill only when the task matches it, and open its `references/` and `assets/` files only when SKILL.md points you there.

### Rules

- [agents-md](.agents/rules/agents-md.md) — Keep AGENTS.md and CLAUDE.md as the project's map — folders, tech stack, ports, install, run, test and build commands. Always on.
- [folder-structure](.agents/rules/folder-structure.md) — Standard folder structure for frontend and backend projects — components, views, hooks, services, types on the frontend; routes, services, data, types on the backend; one type per file. Always on.

### Skills

- [code-standards](.agents/skills/code-standards/SKILL.md) — Apply and review clean code standards — file and function size limits, guard clauses, parameter objects, constants for magic values, variable placement, comments and secrets. Use when writing, refactoring or reviewing TypeScript/JavaScript code, or when the user asks for clean code, a code review or a refactor.
- [conventional-commits](.agents/skills/conventional-commits/SKILL.md) — Write git commit messages following the Conventional Commits spec. Use when the user asks to commit, write a commit message, or squash/reword commits.
- [create-prd](.agents/skills/create-prd/SKILL.md) — PRD — Product Requirements Document. Use when the user asks for a PRD or wants to define the requirements and scope of a new feature or product (first step of the PRD → TechSpec → tasks flow). Do not use for technical specifications (create-techspec) or to break requirements down into tasks (create-tasks).
- [create-tasks](.agents/skills/create-tasks/SKILL.md) — Tasks — breakdown of a feature into implementation tasks based on the existing PRD and TechSpec in `tasks/prd-*/`. Use when the user asks to break a feature down into tasks or plan its execution. Do not use to draft the PRD (create-prd) or the TechSpec (create-techspec).
- [create-techspec](.agents/skills/create-techspec/SKILL.md) — TechSpec — technical specification derived from an existing PRD. Use when the user asks for a TechSpec or the architecture of a feature that already has a PRD in `tasks/prd-*/prd.md`. Do not use without a PRD (create-prd) or to break it down into tasks (create-tasks).
- [javascript](.agents/skills/javascript/SKILL.md) — Write and review modern JavaScript/TypeScript at the language level — no var, strict equality, strict typing without any, function declarations for main functions and arrows for callbacks, flat ternaries, and typed parameter/return objects. Use whenever writing or reviewing .js/.ts/.jsx/.tsx code, or setting up tsconfig/lint rules.
- [node](.agents/skills/node/SKILL.md) — Build and review Node.js + TypeScript backends — async/await, non-blocking event loop (worker threads for heavy work), dotenv configuration, graceful shutdown, a centralized logger adapter, lockfiles and no circular dependencies. Use when creating or changing a Node.js API, server, worker or CLI, or when setting up backend infrastructure code.
- [react](.agents/skills/react/SKILL.md) — Build and review React + TypeScript frontends — small functional components (≤30 lines), custom use* hooks for logic, services for API calls, explicit props (no spreading), minimal useEffect, useMemo for heavy work, accessibility (aria-*) and Tailwind. Use when creating or refactoring React components, hooks, screens or frontend folder structure.
- [run-qa](.agents/skills/run-qa/SKILL.md) — QA — validate and stabilize an implemented feature against the PRD, the TechSpec and the tasks: unit, integration and E2E tests with the available browser tool, accessibility, responsiveness, fixing the bugs found and a final report with evidence. Use when the user asks to run QA. Do not use to implement new tasks or to review the code (run-review).
- [run-review](.agents/skills/run-review/SKILL.md) — Code review — review and stabilize the code of a feature for compliance with the project rules, adherence to the TechSpec and to the tasks, and tests, with a final report and verdict. Use when the user asks to review code, run a code review, validate compliance with the rules or fix problems found during the review. Do not use to validate behavior in QA (run-qa) or to implement new tasks.
- [run-task](.agents/skills/run-task/SKILL.md) — Task — identify and implement the next task of a feature based on the PRD, the TechSpec and the tasks.md, marking it as done at the end. Use when the user asks to run, implement or start a task/subtask, or to continue implementing a feature. Do not use to review (run-review) or validate in QA (run-qa) what has already been implemented.
- [tests](.agents/skills/tests/SKILL.md) — Write and review automated tests with Vitest and Playwright — unit/integration/E2E following FIRST, AAA/Given-When-Then, the test pyramid and an 80% coverage target prioritized by business criticality. Use when writing code that needs tests, adding or fixing tests, setting up a test suite, raising coverage, or reviewing test quality.
